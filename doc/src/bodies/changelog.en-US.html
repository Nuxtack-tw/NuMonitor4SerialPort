V26.8.0 2026-07-31
🆕RS-232 signal panel

🚦 A row of handshake indicators under the header

Every RS-232 control line at a glance — and the output signals are click-to-toggle.

  • LOCAL (OUT): BRK / RTS / DTR — click an indicator to toggle that output; disabled while offline
    • Shown unlit until the first click: the browser can set output signals but cannot read their current state
    • NuMonitor deliberately does not set DTR/RTS on connect, because on most Arduino and ESP32 boards those lines drive the auto-reset circuit
  • REMOTE (IN): DCD / DSR / CTS / RI — read-only, refreshed every 250 ms
  • ACT — blinks whenever bytes move in either direction
  • ERR — flashes red for three seconds on framing, parity, buffer-overrun or received-break errors; click to clear. Reading now recovers automatically instead of dropping the connection
⚠️About parity errors
  • Ports are opened as 8N1 (no parity), so a parity error cannot occur — in practice ERR responds to framing, overrun and break conditions
  • Detecting genuine parity errors would require exposing parity / data-bit / stop-bit settings in the interface first

V26.6.0 2026-07-31
🆕Reconnects after a page reload

🔄 No more clicking Connect after every refresh

If the port you used last is still there, NuMonitor reconnects on load and restores the baud rate with it.

  • Three conditions must all hold
    • Auto-reconnect is switched on
    • You did not disconnect deliberately last time (a device being unplugged does not count)
    • The port is still present and authorised
  • If the port is missing, NuMonitor does not start polling — grabbing a port on page load would block other programs such as the Arduino IDE
  • A failed auto-connect logs a single line instead of opening the full troubleshooting panel
🔧Fixes
  • The auto-reconnect switch now remembers its state — previously it reverted to on after every reload
  • The remembered port record now includes the baud rate, so that is restored too

V26.4.0 2026-07-31
🆕Connection status merged into the button

🔗 The separate "Disconnected / Connected" indicator is gone

The button is the status light: colour tells you the state, the label tells you what clicking will do.

  • Three states, three colours
    • Blue "Connect" — not connected
    • Green "Connected" — connected, with a slow breathing glow
    • Orange "Connecting…" — device lost, auto-reconnect in progress, faster rhythm
  • Hovering previews the consequence: connected turns red and reads "Disconnect"; reconnecting turns red and reads "Cancel". The animation stops so you are not clicking a moving target
  • Clicking while reconnecting cancels the retry (it previously started a separate connection attempt)
  • The plug and cross icons were dropped in favour of the status colour, making the button narrower

V26.1.0 2026-07-30
🆕One button for connect and disconnect

🔌 "Select Port" and "Disconnect" merged into a split button

Blue "Connect" when idle, red "Disconnect" once connected — and no port dialog on every use.

  • The port dialog no longer appears every time. Clicking Connect tries, in order:
    • the port used last time
    • a port whose chipset is recognised (CH340 / CP210x / FTDI / ESP32 / Arduino and friends)
    • the only authorised port, if there is exactly one
    • and only then the browser's port picker
  • The ▾ arrow opens a port menu
    • Lists every authorised port with its custom label or chipset name; identical devices are distinguished by #index
    • The port used last is marked with ★
    • The final entry, Other… (browser picker), authorises a new device
  • The last port is remembered in local storage along with its VID/PID and index
V26.0.0 2026-07-30
🆕Year-based version numbers

🔢 Switching to Va.b.c

From this release a is the last two digits of the year (2026 → 26), b counts features and c counts fixes; incrementing a segment resets the ones after it. v3.0.1 was the last release under the old semantic scheme.

  • The <title> element became the single source of truth for the version number
    • The header badge reads it at runtime instead of hard-coding it
    • The console startup message does the same, so the number can never drift between places
  • Snapshot workflow added: every release freezes the current file into backup/ before changes begin
