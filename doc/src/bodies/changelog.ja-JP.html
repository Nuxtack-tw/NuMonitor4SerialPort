V26.8.0 2026-07-31
🆕RS-232 信号パネル

🚦 ヘッダーの下にハンドシェイク信号の列

RS-232 の制御線をひと目で把握でき、出力信号はクリックで切り替えられます。

  • LOCAL (OUT)：BRK / RTS / DTR — 表示をクリックするとその出力を切り替えます。未接続時は無効です
    • 最初にクリックするまでは消灯のまま表示されます。ブラウザは出力信号を設定できますが、現在の状態を読み取ることはできません
    • NuMonitor は接続時に DTR/RTS を意図的に設定しません。ほとんどの Arduino・ESP32 ボードでは、その線が自動リセット回路につながっているためです
  • REMOTE (IN)：DCD / DSR / CTS / RI — 読み取り専用で、250 ms ごとに更新します
  • ACT — どちらの向きであれバイトが流れるたびに点滅します
  • ERR — フレーミング、パリティ、バッファオーバーラン、ブレーク受信のエラーで赤く 3 秒点滅します。クリックで消せます。接続を切らずに受信が自動的に復帰するようになりました
⚠️パリティエラーについて
  • ポートは 8N1（パリティなし） で開かれるため、パリティエラーは発生し得ません。実際には ERR はフレーミング・オーバーラン・ブレークに反応します
  • 本物のパリティエラーを検出するには、まず画面にパリティ / データビット / ストップビットの設定を追加する必要があります

V26.6.0 2026-07-31
🆕ページ再読み込み後に自動で接続

🔄 更新のたびに「接続」を押す必要はもうありません

前回使ったポートがまだ存在していれば、読み込み時に接続し、ボーレートも一緒に復元します。

  • 次の 3 つの条件をすべて満たす必要があります
    • 自動再接続がオンであること
    • 前回、自分で切断していないこと（デバイスが抜かれた場合は該当しません）
    • そのポートが今も存在し、許可されていること
  • ポートが見つからない場合、NuMonitor はポーリングを 開始しません。ページを開いた瞬間にポートを掴むと、Arduino IDE など他のプログラムを妨げるためです
  • 自動接続に失敗したときは、トラブルシューティングのパネルを開かず 1 行だけ記録します
🔧修正
  • 自動再接続スイッチの状態が記憶されるようになりました — 以前は再読み込みのたびにオンへ戻っていました
  • 記憶するポートの情報にボーレートを含めたため、そちらも復元されます

🆕接続状態をボタンに統合

🔗 独立した「未接続 / 接続済み」表示を廃止

ボタンそのものが状態ランプです。色が今の状態を、文字がクリックしたときに起きることを示します。

  • 3 つの状態、3 つの色
    • 青「接続」 — 未接続
    • 緑「接続済み」 — 接続中。ゆっくり呼吸する光つき
    • オレンジ「接続中…」 — デバイスを見失い、自動再接続の最中。リズムは速めです
  • カーソルを乗せると結果が先に分かります。接続済みなら赤くなって「切断」、再接続中なら赤くなって「取消」と表示されます。動く的をクリックさせないよう、アニメーションは止まります
  • 再接続中にクリックすると再試行を中止します（以前は別の接続試行が始まっていました）
  • プラグと×のアイコンは状態色に任せて廃止し、ボタンを細くしました

V26.1.0 2026-07-30
🆕接続と切断を 1 つのボタンに

🔌 「ポート選択」と「切断」を分割ボタンに統合

待機中は青い「接続」、接続すると赤い「切断」。しかも毎回ポート選択ダイアログが出ることはありません。

  • ポート選択ダイアログが毎回出ることはなくなりました。「接続」をクリックすると、次の順に試します。
    • 前回使ったポート
    • チップが判別できるポート（CH340 / CP210x / FTDI / ESP32 / Arduino など）
    • 許可済みのポートがちょうど 1 つだけなら、そのポート
    • そこまで駄目なら、はじめてブラウザのポート選択画面
  • ▾ の矢印でポートメニューが開きます
    • 許可済みのすべてのポートを、独自ラベルまたはチップ名とともに並べます。同一機種は #番号 で区別します
    • 前回使ったポートには ★ が付きます
    • 最後の項目 その他…（ブラウザの選択画面） から新しいデバイスを許可できます
  • 最後に使ったポートは、VID/PID と番号とともにローカルストレージへ記憶されます
