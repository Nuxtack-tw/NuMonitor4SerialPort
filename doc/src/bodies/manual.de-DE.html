🎯 Einführung

NuMonitor ist ein Monitor für serielle Schnittstellen für Arduino, ESP32, Modems und die allgemeine Embedded-Entwicklung. Er ersetzt den Serial Monitor der Arduino IDE durch Live-Diagramme, GPS-Tracking und vollständige RS-232-Signalsteuerung — alles aus einer einzigen HTML-Datei, die direkt im Browser läuft.

Nichts zu installieren. Online ausführen unter nuxtack-tw.github.io/NuMonitor4SerialPort, oder die einzelne HTML-Datei herunterladen und lokal öffnen.

NuMonitor baut auf der Web Serial API auf, die nur in Chromium-basierten Browsern implementiert ist. Die API verlangt außerdem einen sicheren Kontext: HTTPS, localhost oder eine lokale file://-Seite — alle drei funktionieren.

Hardware

Alles, was sich als serielle Schnittstelle meldet: Arduino-Boards, ESP32-Module, USB-Seriell-Adapter (CH340/CH343, CP210x, FTDI, PL2303), Mobilfunkmodems, Industriegeräte mit RS-232-Anschluss und so weiter. NuMonitor erkennt rund zwanzig verbreitete USB-Seriell-Chipsätze anhand der VID:PID und zeigt einen sprechenden Namen an.

🚀 Schnellstart

Schritt 1 — NuMonitor öffnen

Entweder die gehostete Version aufrufen oder NuMonitor4SerialPort.html aus einer lokalen Kopie öffnen. Keine Installation, kein Build-Schritt.

Schritt 2 — Gerät verbinden

  1. Das Gerät an einen USB-Anschluss anstecken
  2. Auf Verbinden klicken
    • Beim ersten Mal: Der Browser zeigt seine Portauswahl — wählen Sie Ihr Gerät
    • Danach: Die Verbindung zum selben Port wird automatisch wiederhergestellt, ohne Dialog
  3. Für einen anderen Port klicken Sie auf das ▾ neben der Schaltfläche und wählen einen aus der Liste, oder Sie wählen Andere… (Browser-Auswahl), um ein neues Gerät zu autorisieren
  4. Sobald verbunden, wird die Schaltfläche grün „Verbunden“ mit einem langsam pulsierenden Leuchten, und der Pfeil des Portmenüs verschwindet. Fahren Sie mit der Maus darüber, wird sie rot — ein Klick auf Trennen beendet die Verbindung
  5. Wird das Gerät abgezogen, wird die Schaltfläche orange „Verbinde…“ und versucht es jede Sekunde erneut, bis das Gerät zurück ist; ein Klick bricht den Wiederholversuch ab

Schritt 3 — Baudrate einstellen

Wählen Sie die Rate, die zu Ihrem Gerät passt — bei Arduino-Sketches ist das der Wert, den Sie an Serial.begin() übergeben haben. Verfügbare Raten: 300, 1200, 2400, 4800, 9600, 19200, 38400, 57600, 74880, 115200 (Vorgabe), 230400, 250000, 500000, 1000000 und 2000000 Baud.

Die Baudrate wird zusammen mit dem Port gespeichert, sodass ein Neuladen der Seite beides wiederherstellt.

Wirre Zeichen? Das liegt fast immer an einer nicht passenden Baudrate. Ports werden als 8N1 geöffnet (8 Datenbits, keine Parität, 1 Stoppbit) — das verwendet die überwiegende Mehrheit der Geräte.

URL-Erkennung

Links, die im Datenstrom auftauchen, werden automatisch anklickbar: https://, http://, www. (https wird angenommen) und ftp://.

Zeilenenden

Die Auswahl rechts vom Eingabefeld bestimmt, was an alles Gesendete angehängt wird:

OptionGesendete BytesWofür
Keine(nichts wird angehängt)Wenn Sie jedes Byte selbst bestimmen
LF\n (0x0A)Arduino-/ESP32-Sketches mit readStringUntil('\n') — die Vorgabe
CR\r (0x0D)AT-Befehle an Modems und die meisten CLI-Firmwares
CRLF\r\nGeräte im Windows-Stil und einige Module
⚠️ Sie sprechen mit einem Modem? Wählen Sie CR. Der AT-Befehlssatz schließt Befehle mit einem Carriage Return ab. Senden Sie LF oder gar nichts, wartet das Modem weiter auf das Abschlusszeichen — Sie bekommen überhaupt keine Antwort. Das ist kein Verbindungsfehler; der Befehl galt schlicht nie als vollständig.

Diese Einstellung wird gespeichert und beim nächsten Öffnen der Seite wiederhergestellt.

🚦 RS-232-Signalleiste

Sobald eine Verbindung besteht, erscheint unter der Kopfzeile eine Reihe von Handshake-Anzeigen; im getrennten Zustand ist die ganze Reihe ausgeblendet.

LOCAL (OUT) — Ihre Ausgänge, zum Umschalten anklicken

AnzeigeVollständiger NameHinweise
BRKBreakErzeugt eine Break-Bedingung. Einmal klicken zum Starten, erneut zum Aufheben
RTSRequest To SendSendeanforderung — wird von Geräten mit Hardware-Flusskontrolle meist vorausgesetzt
DTRData Terminal ReadyDie meisten Modems nehmen keine Befehle an, solange DTR nicht gesetzt ist

Warum leuchten sie anfangs nicht? Die Web Serial API kann Ausgangssignale zwar setzen, aber nicht zurücklesen. Bis Sie eines anklicken, kennt NuMonitor dessen Zustand schlicht nicht und zeigt deshalb die ehrliche Antwort, statt zu raten, was der Browser beim Öffnen getan hat.

⚠️ Für Arduino- und ESP32-Nutzer: Auf den meisten Entwicklungsboards steuern DTR und RTS die Auto-Reset-Schaltung; ein Umschalten kann das Board neu starten. NuMonitor rührt diese Signale beim Verbinden bewusst nie an — die Entscheidung liegt ganz bei Ihnen.

REMOTE (IN) — Ausgänge des Geräts, nur lesbar

AnzeigeVollständiger NameLeuchtet, wenn
DCDData Carrier DetectTräger vorhanden — ein Modem hat eine Verbindung aufgebaut
DSRData Set ReadyDas Gerät ist mit Strom versorgt und bereit
CTSClear To SendDas Gerät ist bereit, Daten anzunehmen
RIRing IndicatorEin Rufsignal wurde erkannt

Diese vier werden alle 250 ms abgefragt — die Web Serial API bietet keine Ereignisse für Signalwechsel, also bleibt nur Polling.

ACT und ERR

  • ACT — blinkt, sobald Bytes in eine der beiden Richtungen fließen. Bei durchgehender Übertragung wirkt es dauerhaft erleuchtet
  • ERR — wird rot und blinkt drei Sekunden lang bei einem Framing-, Paritäts-, Pufferüberlauf- oder empfangenen Break-Zustand; zum vorzeitigen Zurücksetzen anklicken. Die Verbindung wird nicht getrennt — das Lesen wird automatisch fortgesetzt

Zu Paritätsfehlern: Ports werden derzeit als 8N1 geöffnet — ohne Paritätsbit kann kein Paritätsfehler auftreten, in der Praxis reagiert ERR also auf Framing-, Überlauf- und Break-Zustände.

📈 Plotter

Automatisches Parsen

Es muss nichts konfiguriert werden. Geben Sie vom Gerät einfachen Text aus, und NuMonitor entscheidet, was dargestellt wird: Jede Zeile mit mindestens einer auswertbaren Zahl wird zu Daten; alles andere bleibt einfacher Terminaltext.

Cursor auf der X-Achse

Bewegen Sie den Zeiger über das Diagramm, um den exakten Wert jeder Datenreihe an diesem Messpunkt abzulesen.

Zoomen mit dem Mausrad

Scrollen über einem Diagramm ändert die Anzahl der angezeigten Messwerte, von 20 bis 2000 (Vorgabe 100). Im Speicher werden bis zu 500 Messwerte pro Datenreihe vorgehalten.

Interaktion mit der Legende

Klicken Sie auf einen Legendeneintrag, um die Datenreihe aus- oder einzublenden; ein Klick auf das Farbfeld ändert die Farbe, die gespeichert wird.

📊 Diagrammtypen

Hinweis: map ist kein gültiger Diagrammtyp. {X|0|1|map} fällt auf line zurück. Die Karte ist ein Ansichtsumschalter, der auf jedem Tab erscheint, dessen Daten Koordinaten mitführen.

Die Karte aktivieren

Hängen Sie map:Breite,Länge an eine beliebige Datenzeile an. Auf diesem Tab erscheint eine Schaltfläche 🗺️.

Kartensteuerung

  • Spurpunkte — wie viele der letzten Positionen auf der Karte bleiben, von 1 bis 100 (Vorgabe 10)
  • Folgen — hält die neueste Position zentriert; ausschalten, um frei zu verschieben und zu zoomen, ohne dass die Karte zurückspringt
  • Ein Klick auf einen Spurmarker zeigt die Koordinaten und die an diesem Punkt aufgezeichneten Datenwerte

Vollständige Syntax

{Gruppenname|Ymin|Ymax|Diagrammtyp}#Zähler Label:Wert Label=Wert map:lat,lng

Felder

FeldErforderlichHinweise
GruppennameNeinWird zu einem Tab. Beliebiger Text, auch nicht-lateinische Schriften

Datenpunkte schreiben

Serial.println("Temp:25.5 Humidity:60.2"); // Schlüssel:Wert — empfohlen Serial.println("Temp=25.5 Humidity=60.2"); // Schlüssel=Wert Serial.println("25.5 60.2 1013.2"); // bloße Zahlen → CH1, CH2, CH3 Serial.println("Temp\t25.5"); // Label [Tab/Leerzeichen] Wert
  • Trennzeichen: Leerzeichen, Komma oder Tabulator
  • Trennzeichen zwischen Label und Wert: : oder =
  • Einheiten werden automatisch entfernt — 25.5°C, 60.2% und 40.5km/h werden alle auf ihre führende Zahl reduziert
  • Nicht auswertbare Token werden übersprungen, ohne den Rest der Zeile zu verwerfen

Beispiel-Sketches

// Umgebungsüberwachung mit Einheiten und einem Messwertzähler void loop() { Serial.print("{Environment|0|100|line}#"); Serial.print(seq++); Serial.print(" Temp:"); Serial.print(readTemp(), 1); Serial.print("°C"); Serial.print(" RH:"); Serial.print(readRH(), 1); Serial.println("%"); delay(100); // 10 Hz } // Drei Tabs auf einmal void loop() { Serial.print("{Temperature|15|35|line}Indoor:"); Serial.print(t1); Serial.print(" Outdoor:"); Serial.println(t2); Serial.print("{System|0|100|bar}CPU:"); Serial.print(cpu); Serial.print(" MEM:"); Serial.println(mem); Serial.print("{Battery|0|100|gauge}Level:"); Serial.println(bat); delay(500); } // Drohnen-Telemetrie mit GPS-Spur void loop() { Serial.print("{Drone|0|120|line}#"); Serial.print(frame++); Serial.print(" Alt:"); Serial.print(alt, 1); Serial.print(" Speed:"); Serial.print(spd, 1); Serial.print(" map:"); Serial.print(lat, 6); Serial.print(","); Serial.println(lng, 6); delay(200); }

❓ FAQ

F: Es werden keine Ports aufgelistet.

A: Prüfen Sie, ob das Gerät angesteckt und der USB-Treiber installiert ist, ob Sie Chrome/Edge/Opera verwenden und ob nicht ein anderes Programm den Port belegt — der Serial Monitor der Arduino IDE ist der übliche Übeltäter.

F: Ich bekomme nur wirre Zeichen.

A: Die Baudrate passt nicht. Stellen Sie NuMonitor auf dieselbe Rate ein wie das Serial.begin() Ihres Geräts.

F: Es erscheint kein Diagramm.

A: Prüfen Sie, ob der Plotter-Schalter (📊) an ist, ob die Zeile mindestens eine auswertbare Zahl enthält und ob Sie nicht bereits die Grenze von 10 Gruppen erreicht haben.

F: Mein Modem antwortet überhaupt nicht auf AT-Befehle.

A: Arbeiten Sie folgende Punkte der Reihe nach ab:

  1. Stellen Sie das Zeilenende auf CR — mit Abstand die häufigste Ursache. AT-Befehle müssen mit einem Carriage Return enden; mit der Vorgabe LF antwortet das Modem nie
  2. Setzen Sie DTR (und RTS, falls das Modem Hardware-Flusskontrolle nutzt) in der Signalleiste. Andere Terminalprogramme ziehen diese Leitungen beim Öffnen automatisch an; NuMonitor tut das bewusst nicht, um Entwicklungsboards nicht zurückzusetzen
  3. Prüfen Sie DSR und CTS — ein dunkles DSR heißt, dass das Gerät keinen Strom hat oder falsch verdrahtet ist; ein dunkles CTS heißt, dass es keine Daten annimmt
  4. Bestätigen Sie die Baudrate
  5. Schalten Sie das Echo ein und beobachten Sie den Zähler der TX-Bytes, um nachzuweisen, dass die Daten den Rechner tatsächlich verlassen haben

F: Was ist der Unterschied zwischen automatischem Wiederverbinden und automatischem Verbinden?

A: Ein einziger Schalter steuert zwei Verhaltensweisen:

  • Gerät wird im verbundenen Zustand abgezogen → es wird jede Sekunde erneut versucht, unbegrenzt, bis es zurück ist
  • Seite wird neu geladen oder erneut geöffnet → es wird wieder mit dem letzten Port verbunden und dessen Baudrate wiederhergestellt

Wenn Sie die Verbindung vor dem Verlassen absichtlich getrennt haben, wird nicht von selbst neu verbunden. Auch der Zustand des Schalters selbst wird gespeichert.

F: ESP32-Verbindungen sind instabil.

A: ESP32-Geräte mit USB CDC können ihr Port-Objekt nach einem Neustart ungültig machen. NuMonitor verwirft das veraltete Handle und fordert den Port erneut über den Browser an — deshalb funktioniert die Wiederverbindung, ohne dass Sie das Gerät erneut auswählen müssen.

F: Wie exportiere ich Daten?

A: Klicken Sie in der Bedienleiste des Diagramms auf CSV, um diese Gruppe zu exportieren.

F: Wie wechsle ich Theme oder Sprache?

A: Über den Mond-/Sonne-Schalter und die Sprachauswahl oben rechts. Beides wird gespeichert. Diagramm- und Terminalfarben richten sich nach dem Theme.
