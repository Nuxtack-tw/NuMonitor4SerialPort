🎯 Introdução

O NuMonitor é um monitor de porta série para Arduino, ESP32, modems e trabalho geral com sistemas embebidos. Substitui o Serial Monitor do Arduino IDE por gráficos em tempo real, seguimento por GPS e controlo total dos sinais RS-232 — tudo a partir de um único ficheiro HTML que corre diretamente no navegador.

Nada para instalar. Execute-o online em nuxtack-tw.github.io/NuMonitor4SerialPort, ou transfira o ficheiro HTML único e abra-o localmente.

O NuMonitor assenta na Web Serial API, que só está implementada em navegadores baseados em Chromium. A API exige também um contexto seguro: HTTPS, localhost ou uma página local file:// — os três funcionam.

Hardware

Tudo o que se apresente como uma porta série: placas Arduino, módulos ESP32, adaptadores USB-série (CH340/CH343, CP210x, FTDI, PL2303), modems celulares, equipamento industrial com porta RS-232, e assim por diante. O NuMonitor reconhece cerca de vinte chipsets USB-série comuns pelo VID:PID e mostra um nome legível.

🚀 Início rápido

Passo 1 — Abrir o NuMonitor

Abra a versão alojada ou abra o NuMonitor4SerialPort.html a partir de uma cópia local. Sem instalação, sem passo de compilação.

Passo 2 — Ligar um dispositivo

  1. Ligue o dispositivo a uma porta USB
  2. Clique em Ligar
    • Da primeira vez: o navegador mostra o seu seletor de portas — escolha o seu dispositivo
    • A partir daí: volta a ligar-se automaticamente à mesma porta, sem caixa de diálogo
  3. Para usar outra porta, clique no ▾ ao lado do botão e escolha uma da lista, ou selecione Outra… (seletor do navegador) para autorizar um novo dispositivo
  4. Depois de ligado, o botão fica verde “Conectado” com um brilho pulsante lento e a seta do menu de portas desaparece. Passe o cursor sobre o botão e este fica vermelho — clique para Desconectar
  5. Se o dispositivo for desligado da porta, o botão fica laranja “Conectando…” e tenta de novo a cada segundo até que este volte; clicar nele nessa altura cancela as tentativas

Passo 3 — Definir a velocidade de transmissão

Escolha a velocidade que corresponde ao seu dispositivo — nos sketches Arduino é o valor que passou a Serial.begin(). Velocidades disponíveis: 300, 1200, 2400, 4800, 9600, 19200, 38400, 57600, 74880, 115200 (predefinição), 230400, 250000, 500000, 1000000 e 2000000 baud.

A velocidade de transmissão é guardada juntamente com a porta, pelo que recarregar a página restaura ambas.

Carateres ilegíveis? Isso é quase sempre uma velocidade de transmissão errada. As portas são abertas como 8N1 (8 bits de dados, sem paridade, 1 bit de paragem), que é o que a esmagadora maioria dos dispositivos utiliza.

Deteção de URL

As ligações que surgem no fluxo tornam-se clicáveis automaticamente: https://, http://, www. (assume-se https) e ftp://.

Terminadores de linha

O seletor à direita da caixa de entrada controla o que é acrescentado a tudo o que envia:

OpçãoBytes enviadosUsar para
Nenhum(nada é acrescentado)Quando controla você mesmo cada byte
LF\n (0x0A)Sketches Arduino/ESP32 que usam readStringUntil('\n') — a predefinição

⚠️ A comunicar com um modem? Selecione CR. O conjunto de comandos AT termina os comandos com um retorno de carro. Envie LF ou nada e o modem fica à espera do terminador — não obtém resposta nenhuma. Isso não é uma falha de ligação; o comando simplesmente nunca foi considerado completo.

Esta definição é memorizada e reposta da próxima vez que abrir a página.

🚦 Painel de sinais RS-232

Assim que a ligação é estabelecida, aparece por baixo do cabeçalho uma linha de indicadores de handshake; enquanto estiver desligado, toda a linha permanece oculta.

LOCAL (OUT) — as suas saídas, clique para alternar

IndicadorNome completoNotas
BRKBreakAtiva uma condição de break (interrupção). Clique uma vez para iniciar, outra para libertar
RTSRequest To SendPedido de envio: normalmente exigido por dispositivos com controlo de fluxo por hardware
DTRData Terminal ReadyA maioria dos modems não aceita comandos enquanto o DTR não estiver ativo

Porque começam apagados? A Web Serial API consegue definir os sinais de saída, mas não consegue lê-los de volta. Enquanto não clicar num deles, o NuMonitor não sabe realmente o seu estado, pelo que mostra a resposta honesta em vez de adivinhar o que o navegador fez ao abrir a porta.

⚠️ Utilizadores de Arduino e ESP32: na maioria das placas de desenvolvimento, o DTR e o RTS comandam o circuito de auto-reset, pelo que alterná-los pode reiniciar a placa. O NuMonitor nunca toca nestes sinais ao ligar, deliberadamente — a decisão é inteiramente sua.

REMOTE (IN) — saídas do dispositivo, apenas leitura

IndicadorNome completoAceso significa
DCDData Carrier DetectPortadora presente — um modem estabeleceu uma ligação
DSRData Set ReadyO dispositivo está alimentado e pronto
CTSClear To SendO dispositivo está disposto a aceitar dados
RIRing IndicatorFoi detetado um sinal de toque

Estes quatro são consultados a cada 250 ms — a Web Serial API não expõe eventos de mudança de sinal, pelo que a consulta cíclica é a única opção.

ACT e ERR

  • ACT — pisca sempre que circulam bytes em qualquer das direções. Durante uma transferência contínua parece ficar sempre aceso
  • ERR — fica vermelho e pisca durante três segundos perante um erro de enquadramento (framing), de paridade, de excesso de buffer (overrun) ou a receção de um break; clique nele para limpar mais cedo. A ligação não é terminada — a leitura prossegue automaticamente

Sobre os erros de paridade: atualmente as portas são abertas como 8N1 — sem bit de paridade não pode ocorrer um erro de paridade, pelo que, na prática, o ERR responde a condições de enquadramento, excesso de buffer e break.

📈 Plotter

Interpretação automática

Não é preciso configurar nada. Imprima texto simples a partir do dispositivo e o NuMonitor decide o que representar graficamente: qualquer linha que contenha pelo menos um número interpretável passa a ser dados; tudo o resto continua a ser texto simples do terminal.

Cursor do eixo X

Desloque o ponteiro sobre o gráfico para ler o valor exato de cada série nessa amostra.

Deslocar para ampliar

Deslocar a roda do rato sobre um gráfico altera quantas amostras são apresentadas, de 20 até 2000 (100 por predefinição). São mantidas em memória até 500 amostras por série.

Interação com a legenda

Clique numa entrada da legenda para ocultar ou mostrar essa série; clique na respetiva amostra de cor para mudar a cor, que fica memorizada.

📊 Tipos de gráfico

Nota: map não é um tipo de gráfico válido. Escrever {X|0|1|map} recai em line. O mapa é um comutador de vista que aparece em qualquer separador cujos dados incluam coordenadas.

🗺️ Seguimento por GPS

Ativar o mapa

Acrescente map:latitude,longitude a qualquer linha de dados. Aparece um botão 🗺️ nesse separador.

Controlos do mapa

  • Pontos de trajeto — quantas posições recentes permanecem no mapa, de 1 a 100 (10 por predefinição)
  • Seguir — mantém a posição mais recente centrada; desative-o para deslocar e ampliar livremente sem que o mapa volte a saltar para trás
  • Clicar num marcador do rasto mostra as coordenadas e os valores de dados registados nesse ponto

Escrever pontos de dados

Serial.println("Temp:25.5 Humidity:60.2"); // Chave:Valor — recomendado Serial.println("Temp=25.5 Humidity=60.2"); // Chave=Valor Serial.println("25.5 60.2 1013.2"); // números isolados → CH1, CH2, CH3 Serial.println("Temp\t25.5"); // Etiqueta [tab/espaço] Valor
  • Separadores: espaço, vírgula ou tabulação
  • Separador entre etiqueta e valor: : ou =
  • As unidades são removidas automaticamente — 25.5°C, 60.2% e 40.5km/h são todos interpretados pelo número inicial
  • Os elementos que não são interpretáveis são ignorados sem descartar o resto da linha

Sketches de exemplo

// Monitorização ambiental com unidades e um contador de amostras void loop() { Serial.print("{Environment|0|100|line}#"); Serial.print(seq++); Serial.print(" Temp:"); Serial.print(readTemp(), 1); Serial.print("°C"); Serial.print(" RH:"); Serial.print(readRH(), 1); Serial.println("%"); delay(100); // 10 Hz } // Três separadores em simultâneo void loop() { Serial.print("{Temperature|15|35|line}Indoor:"); Serial.print(t1); Serial.print(" Outdoor:"); Serial.println(t2); Serial.print("{System|0|100|bar}CPU:"); Serial.print(cpu); Serial.print(" MEM:"); Serial.println(mem); Serial.print("{Battery|0|100|gauge}Level:"); Serial.println(bat); delay(500); } // Telemetria de drone com rasto GPS void loop() { Serial.print("{Drone|0|120|line}#"); Serial.print(frame++); Serial.print(" Alt:"); Serial.print(alt, 1); Serial.print(" Speed:"); Serial.print(spd, 1); Serial.print(" map:"); Serial.print(lat, 6); Serial.print(","); Serial.println(lng, 6); delay(200); }

❓ FAQ

P: Não aparece nenhuma porta na lista.

R: Verifique se o dispositivo está ligado, se o controlador USB está instalado, se está a usar o Chrome/Edge/Opera e se nenhum outro programa está a ocupar a porta — o Serial Monitor do Arduino IDE é o suspeito do costume.

P: Só recebo carateres ilegíveis.

R: A velocidade de transmissão não corresponde. Defina no NuMonitor a mesma velocidade do Serial.begin() do seu dispositivo.

P: Não aparece nenhum gráfico.

R: Verifique se o comutador do plotter (📊) está ativado, se a linha contém pelo menos um número interpretável e se ainda não atingiu o limite de 10 grupos.

P: O meu modem não responde de todo aos comandos AT.

R: Percorra estes pontos por ordem:

  1. Defina o terminador de linha como CR — de longe a causa mais comum. Os comandos AT têm de terminar com um retorno de carro; com o LF predefinido, o modem nunca responde
  2. Ative o DTR (e o RTS, se o modem usar controlo de fluxo por hardware) a partir do painel de sinais. Outros programas de terminal ativam-nos automaticamente ao abrir a porta; o NuMonitor não o faz deliberadamente, para evitar reiniciar placas de desenvolvimento
  3. Verifique o DSR e o CTS — DSR apagado significa que o dispositivo não tem alimentação ou está mal ligado; CTS apagado significa que não está a aceitar dados
  4. Confirme a velocidade de transmissão
  5. Ative o eco e observe o contador de bytes TX para provar que os dados saíram mesmo do computador

P: Qual é a diferença entre religação automática e ligação automática?

R: Um único interruptor governa dois comportamentos:

  • Dispositivo desligado da porta durante a ligação → tenta de novo a cada segundo, indefinidamente, até que volte
  • Página recarregada ou reaberta → volta a ligar-se à última porta e repõe a respetiva velocidade de transmissão

Se se desligou deliberadamente antes de sair, não volta a ligar-se por iniciativa própria. O próprio estado do interruptor também é memorizado.

P: As ligações ao ESP32 são instáveis.

R: Os dispositivos ESP32 com USB CDC podem invalidar o respetivo objeto de porta após um reinício. O NuMonitor descarta o identificador obsoleto e volta a obter a porta através do navegador, razão pela qual a religação funciona sem que tenha de voltar a escolher o dispositivo.

P: Como exporto os dados?

R: Clique em CSV na linha de controlos do gráfico para exportar esse grupo.

P: Como mudo o tema ou o idioma?

R: Use o comutador lua/sol e o seletor de idioma no canto superior direito. Ambos são memorizados. As cores do gráfico e do terminal acompanham o tema.

A ligação Manual e o distintivo de versão acompanham igualmente o idioma da interface.
